# Governance + Codex adoption

Status: accepted plan; specification work complete, implementation pending. Updated 2026-09-19.
Supersedes the independent-companion/Cowork adoption parts of the earlier proposal. It does not
reopen or mislabel the completed architecture-reset implementation.

## Slice 1: one supported governance product and one useful loop

- [x] Specify governance-required bundling, Codex-only scope and legacy capability boundaries.
- [x] Specify bounded analytics, qualification, indexing gate, decision interface and benefit assumptions.
- [x] Map current, first-release and destination flows; connect hook/device costs to an ordered plan.
- [ ] Qualify the current core through the actual Codex app: session reopen, interruption, compaction,
  linked worktrees and two cooperating sessions. Start with explicit commands, then native hooks.
- [ ] In governance's own project, add one release-manifest/lock migration and companion packaging.
  Preserve Python/TypeScript boundaries; no rewrite or second installer. Test activation recovery.
- [ ] Add bounded analytics/report and lightweight regression/performance runner in this module.
- [ ] Connect one next-proof packet and a real local check to existing governance plans/receipts.
  Make manual-then-hook duplication visible and follow the one-gate path; no new verdict cache.
- [ ] Qualify exact published artifacts and establish a reproducible baseline/pilot comparison.

Exit: a new Codex session resumes useful context and the original pending job; the adopter uses one
install/update path; repeated orchestration can be measured; mandatory proof remains intact. Existing
71-test receipts are prior core evidence, not qualification of these new features.

## Slice 2: one expensive project workflow

- [ ] Pick one project/device lane by observed queue/build/install/test and coordination cost.
- [ ] Integrate its existing runner and resource owner. Preserve source/binary/device/environment
  identity, claims, cleanup and full-log references; distinguish simulator and physical proof.
- [ ] Remove observed redundant invocations, use owner-proven build/install reuse and focused rechecks.
- [ ] Pilot a second project on Codex; compare accepted work and later rework, not just faster checks.

Exit: one device workflow measurably improves without missed claims or new scheduling infrastructure.
Changes in adopter/governance repositories are separate scoped work; those repos remain read-only here.

## Slice 3: add only demonstrated value

- [ ] Shallow repository map if repeated discovery warrants it.
- [ ] One bounded semantic decision experiment, preferably residual failure triage, through the
  provider-neutral interface. JEV starts in shadow mode; promotion requires replacing costly work.
- [ ] Read-only release fact packet using existing collectors if recurring bookkeeping merits it.

No fixed ordering between these experiments: choose the measured bottleneck. Do not deploy them all
merely because interfaces exist. The core remains usable with no optional model or index.

## Destination, not current commitments

An owned front end, richer proof coordination, Mnemos projection, repository consolidation and other
hosts require separate evidence and scope decisions. Cowork is explicitly deferred, not the next
mandatory milestone. No universal scheduler, general cache, autonomous publication or provider cascade.
