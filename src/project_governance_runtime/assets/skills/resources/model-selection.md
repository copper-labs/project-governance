# Fixed models and optional task categories

Use the operator's selected provider, model and effort. Otherwise use the complete fixed binding
in the caller-selected provider configuration. Keep the running parent and progressing workers
unchanged. A role name, task difficulty or agent preference is not permission to select another model.
This policy does not authorize delegation or additional workers.

## One selection owner

The compiled runtime owns optional category routing at governed `provider-submit`. It is off by
default. `continuity.decisions.consumers.DL08` is the only activation switch, bounded by the global
decision mode. `continuity.model_routing` defines a flat map of operator-authored task categories
and one model/effort pair per category. The existing provider binding owns the fixed baseline.

JEV classifies the task against category descriptions. Code applies the preselected pair only
inside a qualified, already authorized new assignment. Shadow and advice modes keep the baseline.
Missing credentials, uncertainty, unavailable evidence or budget exhaustion keep the baseline.
A started or uncertain worker never triggers an automatic replacement. Other JEV features can be
active while model routing remains off.

Preserve an explicit operator model/effort choice and its provenance. Do not forge an operator
choice by adding a model argument. In a required-governed assignment, use the approved configuration
and route. A baseline hint does not disable enabled routing. Unbound alternate values fail admission.
An unsupported host stays outside enforcement coverage; prompt instructions do not create a sandbox.

## Existing project policy

Preserve `config/governance/model-selection.md` when it exists. Installation and upgrades must not
create or overwrite it. RC4 no longer ships an agent-interpreted work-class recommendation table.
Do not translate an old project table into automatic routing consent or silently keep interpreting
it alongside the runtime router. Report conflicting project guidance as a migration issue. Resolve
it through the operator's fixed binding or deliberate category configuration before routed adoption.
The legacy helper accepts explicit/configured values; it does not acquire a second router.

## Availability and evidence

Provider discovery establishes executable availability, not account access or model capability.
Automatic routing requires applicable native qualification evidence for the exact configured pair
and guarded worker class. Unknown capability is ineligible. Preserve a requested model's failure;
never silently replace its provider, model, effort or access route.

Record the baseline, category suggestion, dispatched pair, actually reported pair, fallback and
available usage in existing assignment evidence. Follow-ups keep their original pair and bound scope.
Measure total work to an accepted result, including repairs and review. Token savings and unobserved
activity stay unknown without comparable outcome evidence. Do not create model pools, price rankings,
retry ladders or extra review jobs merely to exercise routing.
