# External Docs Style Guide

## Trigger

Use this skill when a project needs a style guide for externally consumed docs or when public docs show inconsistent terminology, tone, examples, structure, or support claims.

## Required Reads

- `AGENTS.md`
- existing writing style guide and authoring quality gates
- representative public docs, product terminology, and support/version policy
- target audience and publication channels

## Workflow

1. Define audience, tone, terminology, supported doc types, and source-of-truth rules.
2. Add rules for prerequisites, versioning, examples, screenshots, commands, troubleshooting, and accessibility.
3. Define what must never appear in external docs: internal codenames, secrets, speculative roadmap, unsupported claims, or unexplained acronyms.
4. Include lightweight examples of preferred and discouraged wording.
5. Keep the guide enforceable through prose checks, review skills, and human waivers.

## Validation

Run docs-governance and prose/style validation where configured. Have a reviewer check that the guide matches actual product and support policy.

## Evidence

Report guide path, policy decisions, examples added, validation status, and review or waiver needs.
