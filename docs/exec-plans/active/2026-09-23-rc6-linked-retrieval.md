# RC6 maintained context implementation and qualification

The [RC6 specification](../../specs/engine-rc6-linked-retrieval.md) owns behavior. The operator
accepted the expanded first-release boundary on September 25: automatic prompt entry, a maintained
repository index, basic relationships, bounded JEV selection with expansion, and real-task evidence.
The [research reconciliation](../../research/2026-09-25-repository-index-harness-practices.md)
supplies rationale, not additional mandatory features.

The design review and operator simplification seam are complete. On September 25 the operator
accepted the recommendations and authorized RC6 implementation. Begin at I1 and retain the ordered
qualification gates. The pre-existing dirty implementation and locally qualified archive are
preserved as baseline evidence; they do not satisfy the expanded release scope. Adopter upgrades
remain deliberate and limited to explicitly authorized destinations.

## What is already implemented and what is not

| Baseline | Current evidence | Remaining RC6 obligation |
| --- | --- | --- |
| R0 local entry | Unborn Git, default route, separate local/hosted scope, errors and fallback implemented | Prove ordinary automatic host entry and resolve real required-packet/configuration barriers |
| R1/R2 catalog and JEV | Full eligible inventory, literal descriptions, bounded shared-state batches and explicit partial coverage implemented | Maintain reusable metadata, source ranges and relationships; support explicit widening |
| R2b prompt protocol | Codex hook path, provisional identity and small local history query implemented | Demonstrate native first-read delivery and later task/provider linkage in actual work |
| R5 observations | Usage adapter, expansion/outcome receipts and readiness implemented | Join those observations on ordinary accepted tasks; unknown totals are not complete measurement |
| R5a documentation | Touched-work checks, literal overview clues, gap shortlist and authoring guidance implemented | Feed maintained source facts into the same owners; preserve advisory legacy debt |
| Earlier R3/R4 experiments | Extra excerpt model pass and richer historical projection deferred | Remain deferred; the accepted current-source index is now required and is not the historical projection |

Prior independent corrections closed medium/high findings for the transient implementation. Its
integrated engine proof passed 563 tests before small subsequent corrections, followed by affected
checks and rebuilt archive proof. A ten-turn synthetic JEV trial visited 1,500 paths across turns,
answering 271–334 per turn under its deadline. These establish that earlier candidate's bounded
integration, not complete one-prompt assessment or accepted-development benefit. Exact receipts and
artifact hashes stay outside this product-neutral repository. Reuse them only for unchanged claims.

## Decisions fixed for this iteration

- Keep the supported Codex prompt adapter and fixed coding model. Do not add a new host, scheduler,
  model router, skill-dependent entry or delegation policy.
- Keep current source/docs/task owners. One disposable per-worktree SQLite index lives under the
  external context state root; no task-store migration, daemon or shared cache.
- Reuse TypeScript's packaged parser for TS/JS syntax and existing Markdown/catalog readers.
  Other languages remain searchable with clearly weaker structural coverage.
- Index literal descriptors and ranges. Use exact lookup plus FTS5 descriptor search; keep the full
  metadata-approved inventory independently available to JEV. No embeddings or generated summaries.
- Add declared catalog/document links and resolvable relative static imports. One-hop expansion;
  unresolved links and name-based test guesses must not become dependency facts.
- Use existing DL03 relevance only. Initial entry plus up to two expansions share its existing budget
  partition. Required/exact sources, source validation and fallback remain deterministic.
- Keep worktree-local indexes/runtime selections and session-bound tasks. Qualify a version change
  in one designated integration tree, distribute its tracked pin through Git, and reconcile each
  destination installation at a safe seam. No shared mutable index or upgrade coordinator is added.
- Require ordinary native-host task evidence before RC6 is ready. Source fixtures alone are not the
  release gate. Evidence need not prove a universal savings percentage.
- Run the transient comparison from a frozen external artifact, not a second shipped backend.
  Keep JEV-off and error fallback. Retain only current/active-reader index generations and use one
  refresh operation with a rebuild option. Keep staged indexing, FTS5, reverse/declared links and
  clarified-purpose expansion; the optional feature cuts were not selected.

### I1 — Make the normal entry usable and observable

Dependency: I0 seam resolved.

Owning surfaces: `prompt-context.ts`, `startup-hook-output.ts`, `context-route-command.ts`,
`decision-task-binding.ts`, `context-packet.ts`, `context-doctor.ts`, managed host guidance.

- Reuse existing event parsing and host ownership. Validate raw prompt, workspace/session/turn and
  follow-up intent; keep unbound observations provisional. Add only the missing link from a same-session
  provisional entry to deliberate task creation/resume and later provider submissions.
  Preserve the entry family and frozen purpose on the first task association; do not silently change
  prior questions or rewrite existing job receipts. Clarified purposes must be explicit.
- Audit new-install defaults and existing-profile readiness. Diagnose narrow sharing declarations,
  route gaps, conflicting startup instructions and required-packet size before blaming JEV.
- Keep required policy intact. Provide per-file byte evidence and remediation for overflow; move
  background material only through a reviewed project profile, never classifier-driven demotion.
- Confirm the supported native host can inject the packet before task-specific reads. Run a small
  actual-host qualification in an authorized workspace early, before investing in later slices.
  If the host cannot expose/consume this event, stop dependent release claims and resolve that seam.
- Focused suites: prompt/host parsing, task entry, binding and packet tests. Cover new project, first
  prompt, short bound follow-up, duplicate turn, closed/stale binding, wrong workspace, mandatory
  overflow, no token and matching preparation/submission/read-order identities.
- Exit: useful automatic local packet, or a named required-context blocker; verified native path and
  current-task linkage. No JEV call is required to prove local entry.

First implementation batch, September 25: normal create/fork/resume now appends the first same-session
prompt association; new provider packets and native usage can reference that original entry. The
entry stays immutable, and a later task cannot retarget an existing association. Native turns reserve
before optional preparation, including refused turns, so incomplete later turns cannot select older
completed entries. Recording failure uses provider-free local context. Missing host events or a lost
turn marker still leave attribution coverage unknown and require native qualification.

Doctor now shows required-file sizes/unavailable originals and the Codex preview-limit risk. The
managed hook proposes complete delivery under governance's byte cap; an exact older managed shape
can be reconciled through the backed owner, while custom handlers and native trust remain explicit.
Focused source tests, typechecks and a scoped Opus 5.5 medium review/recheck cover this batch. The
review's two medium corrections are closed. Native Codex qualification subsequently delivered the
entry packet before any tool read and reported the expected source value. That closes I1 host
delivery; it remains an installation qualification, not an I5 accepted development task.

### I2 — Maintain current source facts in SQLite

Dependency: I1 entry and source-view invariants.

Owning surfaces: `context-source-index.ts`, `change-subject.ts`, `context-path-policy.ts`, a small
projection-store module beside those owners, and `context-doctor.ts`. Reuse `node:sqlite`; do not edit
the critical continuity schema or add a generic storage service.

- Implement generation/file/span/relation records from the spec. Store bounded descriptors and source
  ranges with digest/extractor identity. Keep a per-worktree cache and source-view-specific path map.
- Incrementally reuse unchanged facts; invalidate changed/deleted/renamed/ineligible records from the
  current captured inventory. Handle first untracked/staged files and differing linked worktrees.
  Use Git index blob IDs with dirty-state observation for tracked clean files; capture/hash dirty or
  untracked files. Record freshness basis and conservative treatment of unverified Git flags. Source
  revalidation before delivery remains mandatory; size/mtime alone never establishes freshness.
  Distinguish Git blob IDs from extracted-byte digests for EOL/clean/smudge-filtered files; compare
  delivery against the same representation without running untrusted filters for extraction.
- Build/refresh in bounded transactions. Keep unextracted paths represented with named coverage.
  Never synchronously complete an arbitrary full-tree crawl just to answer a prompt.
- Add passive status and one explicit refresh operation with a rebuild option through the context CLI owner. Cache failure
  falls back without touching tasks. Set a documented size cap and bound obsolete-row reclamation;
  no timer, watcher, separate GC command family or background job is required.
  Use snapshot reads and generation-checked publication instead of another refresh-lease service.
  Bound/discard duplicate extraction when same-worktree sessions race. Identify orphaned projection
  ownership before explicit cache removal; never remove history or another tree's active state.
  Retain generations referenced by current worktree/staged maps or active readers only. Reclaim
  unreferenced generations/facts within the existing size/time bounds; do not create an index archive.
- Use FTS5 for descriptors in the same SQLite file and safe exact-name/path lookup. Verify packaged
  Node support; retain exact fallback on missing FTS. No runtime extension download.
- Focused suites: new projection-store and existing source-index/subject suites. Cover warm reuse,
  one-file refresh, staged/unstaged mismatch, deletion/rename, changed extractor, unsafe/binary paths,
  partial refresh, stale source before delivery, writer contention, corrupt/unknown schema, size cap,
  rebuild and two worktrees with different source. Include merge/rebase, worktree deletion/recreation
  at the same path using the existing Git-administration filesystem locator, and two sessions
  publishing in one tree. Distinguish a move from recreation; failed Git lookup or missing birth time
  cannot establish verified cache identity. Include EOL/filter representation and identity fallback.
  Do not reproduce every SQLite unit test.
- Exit: an unchanged second request reuses source facts; one changed file refreshes its affected facts;
  every eligible path remains visible even when extraction is incomplete. Record cold/warm costs.

### I3 — Add useful structure and declared relationships

Dependency: I2 provenance and cache lifecycle.

Owning surfaces: `context-source-index.ts`, existing TypeScript package, document-link/catalog readers,
`context-history.ts`, and a small relationship resolver if needed.

- Use syntax trees for TS/TSX/JS/JSX definitions, signatures, line ranges and static relative
  imports/exports. Do not type-check the adopter or introduce build-dependent compiler resolution.
- Reuse Markdown titles/links and the existing capability catalog. Add source/doc/test/workflow links
  only when current declarations exist. A naming guess stays a search clue.
- Resolve supported relative targets against the captured inventory. Record ambiguities, aliases,
  package imports and dynamic imports as unresolved. Invalidate affected links after source changes.
- Combine one-hop forward/reverse verified links with exact/descriptor search. Keep unrelated modules
  available through the full inventory; a relationship walk cannot confine semantic discovery.
  Reverse results carry extraction coverage and stay partial while possible importers are unparsed.
  Relationship facts stay local; unapproved endpoint paths cannot leak into hosted JEV metadata.
- Keep the current small local history reader. Historical summaries stay background; no new graph
  adapter, historical corpus or source-of-truth mirror.
  Query task/evidence links live from their owner; do not mirror them in the current-source index.
- Feed the same literal overview facts into existing backfill telemetry and documentation owners.
- Focused suites: declarations/ranges, quoted fake declarations, relative resolution/ambiguity,
  Markdown/catalog link provenance, cycles, stale endpoints, source-to-declared-test, unsupported
  language coverage and no extra build/provider call. Existing comment/document tests remain owners.
- Exit: a cross-file failure can surface its source owner, declared test and guide with inspectable
  reasons. No inferred dependency or test-coverage claim is introduced.

### I4 — Select from the whole permitted index and allow expansion

Dependency: I2/I3; preserve I1 automatic entry.

Owning surfaces: `context-metadata.ts`, `context-candidates.ts`, `context-route-command.ts`,
`context-packet.ts`, existing decision budget/runtime and `context-observations.ts`.

- Read cached descriptors without requiring an initial lexical shortlist. Exact/FTS/link candidates
  strengthen deterministic fallback while JEV independently traverses the entire approved inventory.
  Interleave priority and general-inventory slots, reserving at least half each batch for the general
  remainder while both streams exist. Report both counts; no priority result removes other candidates.
- Reuse DL03 shared-state relevance, at most 63 questions per batch, existing source/metadata permission
  separation and one-second call/3.5-second selection bounds. Record partial coverage, never false
  negative/no-match proof. Source descriptions require the existing extra disclosure permission.
- Add entry-linked expansion to `context-route`: explicit originals, one-hop links or continued
  unassessed inventory. Preserve cursor generation and exact question/source/policy identity.
  A clarified purpose can rerank, but cannot reset the family call/byte budget or widen permissions.
  Reconcile source edits by requeuing affected paths/batches while retaining compatible progress.
  Reuse answers only for identical complete semantic input, not a per-file digest if shared evidence
  changed. First task binding preserves the family; later task revisions invalidate incompatible state.
- Share one existing metadata allowance across the initial request and up to two expansions. Resume
  paid exact batches without duplicate spend; changed identities invalidate reuse. Further original
  reads remain available after model-budget exhaustion.
  Extend the existing budget lifecycle explicitly: stable entry-family key, closure after two
  expansions/new same-session root turn/15-minute expiry, durable expenditure and replay identities,
  and named capacity fallback. Qualify any budget-store schema upgrade; do not modify task schema.
  Exclude expired families from capacity admission even if their original callers never return;
  test this through reservation without adding background expiry work.
  Do not allocate paid families for disabled/missing-token entry. Retire expired family-only
  accounting and cursor caches in bounded admission work; immutable entry timestamps prevent
  reopened allowances. Retain ordinary scopes and audit receipts. A completed step can replay
  without spending within its original lifetime; expiry refuses delivery through that cursor.
  Expiry never releases active workflow/resource ownership. New turns have new bounded allowances;
  there is no new session-wide monetary ceiling, so measure follow-up and cumulative session use.
- Deliver deterministic current spans first; do not add another excerpt-selection model pass. Keep
  required/exact source priorities and validate every excerpt before packet output.
- Focused suites: full inventory beyond the old 126-path boundary, misleading names with descriptions,
  explicit source outside lexical hits, restricted sharing, partial/unvisited reporting, cursor resume,
  replay, clarified purpose, source/config changes, total family budget, no match, no token, malformed
  answers, family expiry/concurrent reservations/capacity, provider timeout versus caller cutoff,
  task association without free budget reset, and expansion finding a previously missed span.
- Exit: first packet plus bounded expansion has a useful route beyond every initial shortlist;
  provider-free context remains functional. Increasing JEV call count is not itself an acceptance test.

### I5 — Prove ordinary use and measure the whole path

Dependency: I1–I4 integrated through the normal entry.

Owning surfaces: existing entry/decision/episode/usage/outcome records, evaluation scripts and installed
host adapter. Keep evidence and adopter identities outside this repository.

- Freeze about twelve cases: new repo; exact path; misleading name; relevant path beyond 126 in a large
  inventory; cross-module failure; source-to-test; design constraint; edited/untracked source;
  staged-versus-working source; short follow-up; no match; and expansion after an initial miss.
  Share fixtures for safety/permission/fallback cases rather than building another test framework.
- Compare (A) current transient RC6 retrieval, (B) maintained deterministic retrieval and (C) the same
  maintained index with JEV. Same source/prompt/permissions/delivery budget and coding-model settings.
  Run A from the frozen external artifact with its hash and isolated state. Keep only a test-side
  invocation/output adapter; do not ship an old/new backend switch or remove ordinary JEV-off fallback.
  Mock-provider tests prove all inventory and failure invariants; bounded live JEV proves its actual
  question shape on four informative cases. Repeat ambiguous misses once before interpreting them.
- Run at least two real development tasks through the candidate-installed native host: one code fix
  and one cross-file change involving docs/tests. At least one uses active JEV before task-specific
  reads. Use this development project or an explicitly authorized pilot workspace; do not upgrade or
  interfere with active adopters merely to gather data. Installation checks do not count.
- Link exact candidate hash, source, session/turn, packet submission, first observable read, task
  binding, source expansion, known model response usage, existing checks and explicit acceptance.
  Record extra reads/auxiliary models where observable and name remaining coverage gaps. Never infer
  accepted outcome from a successful provider exit or passing check alone.
- Preserve comparable task criteria and include cold/warm refresh cost, latency, useful source spans,
  subsequent reads, rework and time to completion. Do not sum cumulative provider session counters.
  Prospective evidence and reset paired trials are separate; do not pretend sequential work is blind.
- Focused suites: native response identity/deduplication, continuation linkage, outcome/reopened
  observations and unknown coverage. Do not add a collector on every tool call or an agent that grades
  every trace. Reuse existing native transcripts and explicit host observations.
- Exit: ordinary-host delivery and two accepted outcomes evidenced; controlled expansion recovers a
  miss; no material required-context/permission/freshness/fallback regression. No promised percentage
  savings is required. If all real use/acceptance remains unknown, RC6 is not ready.

  Prove no cross-tree cache/binding leakage, no live-job runtime switch, clear lock/install mismatch,

- Preserve continuity schema 6, worktree/session binding and the existing task owner. Use the

- Rebuild and qualify the exact final archive after corrections. Match version, source SHA, package

  Use the [source-control and Codex workflow guide](../../developer/guides/source-control-and-worktrees.md)

  qualified host coverage, remaining language limits and later adopter outcomes.

## Minimum validation matrix

| Proof boundary | Required evidence | Not a substitute |
| --- | --- | --- |
| Entry | Native prompt before task-specific reads, valid follow-up/binding, required overflow visible | Configured hook or stdin fixture alone |
| Index | Freshness, reuse/invalidation, partial coverage, rebuild and no-token fallback | File count or cache-hit rate alone |
| Relationships | Current source-backed links/ranges; unresolved coverage visible | Similar filenames or inferred dependency graph |
| Selection | Whole permitted inventory independent of lexical hits, budgets/permissions, expansion | More JEV calls or a smaller packet alone |
| Live provider | Four frozen representative cases and at least one real host task using JEV | Provider authentication/adoption probe |
| Ordinary outcome | Two accepted tasks tied to candidate/entry/source; available reads/usage and omissions | Provider exit, synthetic labels or isolated passing checks |
| Release | Final archive and installed proof after review corrections, published asset readback | Old archive or source-only test run |

Use the [validation strategy](../../governance/validation-strategy.md): focused checks per coherent
slice, one integrated release boundary, broaden/repeat only for changed claims or diagnosed failures.
No full application CI or device run is implied by this planning update.

## Deferred scope and stop rules

No graph/vector service, embedding model, generated prose corpus, cross-worktree cache, full
compiler/call graph, advanced aliases, all-language structural parity, JEV-ranked historical prose,
new question families, another model pass, background indexing daemon or automatic delegation.
Do not add these to rescue a failing benchmark without returning to the concrete miss and simpler
fallback. Do not remove accepted features merely to simplify: present candidates and lost capability
at the operator's requested review seam.
