## Evidence and current state

Original synthetic subject tests failed all three cases: unrelated archive membership, locally
restored required input, and a candidate different from HEAD. They now pass. The original detached
failure diagnostic was overwritten with `worker-incomplete`; the correction keeps a bounded capture
cause. Larger committed input still fails at the existing 16 MiB allowance. Independent review found
that review hunks still used live differences and that candidate-only secrets could escape the live
scan. Both owning paths now use the committed candidate; the secret scan also preserves exhaustive
live/index coverage and reuses identical pinned blob scans. The secret regression failed before
correction, including an unchanged candidate file repaired only in later HEAD and a replacement ref.

The approach follows Git's documented pre-push stdin contract:
[Git hook reference](https://git-scm.com/docs/githooks#_pre_push). Exact pushed object identity is
preferable to widening source delivery or snapshotting unrelated archives. The existing streaming
live secret scan retains its independent authority. External documentation establishes the hook
interface, not accepted development benefit or cost savings.

Current: 1,147 engine, 82 continuity and 100 proof-script cases passed; 16 optional browser cases
were skipped. Focused corrections, typecheck and build passed. A clean installed native push
preserved an unrelated large archive and opposing live/index bytes, and refused both live-only and
candidate-only secrets. Independent review corrections are verified. Next: final compiled/package
proof, owned local commit, then deliberate adoption through the installed transition owner with preserved readers,
task history, attachments and unrelated staged bytes. Live ownership is not stale merely because a
chat is idle. An unresolved reader prevents activation until its owning recovery/handoff is qualified.

this source batch. Retirement follows the finite legacy lane described in the kernel contract.
