# RC10 implementation and adoption plan

Owner: [RC10 specification](../../specs/engine-rc10-context-use.md).
Baseline: published RC9.1; retain its one 30-second operation envelope without a per-call cutoff.
The operator approved implementation and local simulation after the Opus 5.5 medium design review,
reconciliation and simplification. Runtime changes are implemented and undergoing integrated
qualification. Publication and adopter upgrades are not complete.
Active identifies this delivery record; the linked release specification is approved.

Follow the [validation strategy](../../governance/validation-strategy.md). Work solo by default for
this linked path; use one independent review at the completed candidate seam rather than a reviewer
for each helper. Keep adopter identities, snapshots, evaluation fixtures and runtime proof outside
this checkout. Check the external planning record for the exact selected worktrees and hashes.

## Progression and first useful boundary

| Order | Batch | Observable result | Dependency |
| --- | --- | --- | --- |
| P0 | Freeze evidence and cases | Concrete failure causes, private cases and a matched comparison contract | Planning |
| P1 | Correct entry use and readiness | Entry provenance and unsupported workspace lookups have clear reasons; host alignment remains adoption work | P0 |
| P2 | Assess efficiently and reuse correctly | More useful semantic coverage; ordinary repeat reads do not pay for another identical selection | P1 |
| P3 | Deliver project procedures | Current prompt receives applicable complete runbook sections alongside source evidence | P1, P2 |
| P4 | Join outcomes and qualify lessons | Recent telemetry shows what was delivered and what remains unknown; harmful completion and recovery cases are covered | P1–P3 |
| P5 | Freeze, review and publish | Reconciled candidate and immutable experimental RC10 | P4 |
| P6 | Adopt and evaluate | One verified ordinary-development pilot, then additional repository shapes | P5 and adopter pause seams |

P1 is the first useful development checkpoint. Test it locally; keep one RC10 publication boundary
for the complete release scope. Do not publish another timeout-only fix or expand into general
computer use/model routing to make this release look larger.

- [x] Pack evidence within ordinary file slots: required/explicit material, intact bounded excerpts

The generated large fixture matches the captured large shape's path count and descriptor-size

Do not qualify a supported case merely because its missing evidence has a recorded reason.
Material stress/permission limits remain visible.
Record configurations that cannot satisfy the full case instead of claiming universal readiness.
No exhaustive device matrix, unrelated app builds, all-model comparison or full GitHub CI during
routine work is needed. Run the declared local release proof at P5.

The original consumed cases now deliver all eight decisive groups in recorded-answer regression
replay. A separate reviewer-authored cohort delivered four of six groups on its first live run;
the failures exposed uncertainty/ranking coupling and an omitted test annotation. The corrected
repeat delivers all six groups with complete permitted metadata assessment. Those repeats are
diagnostic regressions, not fresh independent qualification or proof of accepted-task savings.
Retain the first failures, unchanged expected ranges and configuration differences externally.
The completed-candidate review and exact installed-package proof remain P5 requirements.

Final live regression covers nine consumed cases and twenty decisive groups under the explicitly
declared large-repository profile: 64 captured files, 8 KiB ordinary excerpts and 48,000 optional
packet bytes. All twenty groups reached their packets, with complete permitted metadata answers.
Earlier smaller-profile misses remain retained; defaults have not acquired universal qualification.
Warm selection took approximately 8–19 seconds. Index preparation is measured separately; cold
latency, accepted tasks and token savings remain unqualified.

The final missed pair exposed a literal relationship already held by the index. Packet fitting now
keeps a validated positive test beside its captured, non-negative imported implementation. This adds
no capture, call, pin or permission. The native profile exposes the existing ordinary excerpt
allowance through `optional_excerpt_bytes`, using the manual command's shared validator and limits.
An isolated actual packaged-command run on one frozen repository case independently delivered both
originals in approximately 12.5 seconds. Keep that proof separate from library composition and the
synthetic installed-hook proof; no adopter upgrade or native chat acceptance is implied.

## Simplifications built into this proposal

- Align the native chat with its actual existing checkout; defer transparent cross-worktree routing
  and another session-target registry.
- Use one optional list of existing Markdown procedure sources and the existing index/packet builder;
  no parallel catalog, new skill framework, summary model or executable recipe conversion.
- Keep the present disclosure fields; improve their diagnosis and explicitly revise pilot permissions.
- Choose one qualified wire layout; keep old comparisons in the external evaluator, not a runtime mode.
- Reuse exact packets/answers under existing families; defer fuzzy prompt matching and another cache.
- Use current SQLite telemetry ownership, native usage seams and explicit task outcomes; no new
  collector, model-to-model orchestration or checklist for agents to complete after every read.
- Treat the remaining transcript lessons as focused contract/test improvements; defer autonomous
  routing, broad risk gates and a new verifier loop.

Implementation must flag any new requirement that cannot fit these owners before adding a service,
another authority or another mandatory developer step.
