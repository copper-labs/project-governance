# 4.1 context quality and ordinary-work evidence delivery

## Final state and authorization

The operator approved the four priorities and the always-present task snapshot. The
[specification](../../specs/engine-4-1-context-quality.md) owns R1–R12. This plan begins from
published 4.0.0 and records the authorized source implementation, proof and release order.
The operator authorized implementation. Provider disclosure/live comparisons, publication and
adopter changes remain separately deliberate actions under their existing owners.

Every prompt in an exactly associated chat gets compact task facts through code. The main model
interprets the request. Preparing these facts does not require a phrase list, JEV classification
or another LLM summary. Existing JEV source selection remains separately configured. Retrieval
skipping, skill suggestion and wider log filtering are outside the core release.

Native batch invocation, after declaring its implementation slot complete through the updater:

```sh
project-governance check --stage 4-1-F1 --pack source-4-1 --mode impacted --base-ref HEAD --implementation-plan docs/exec-plans/active/2026-10-05-4-1-context-quality.md --batch F1 --timeout-seconds 1800 --summary
```

Use the matching F0–F5 stage and batch. Source F5 broad proof needs a deliberate larger timeout
when required; a wait expiry does not authorize a retry. The configured source adapter is
`components/engine/scripts/check-4-1-source.mjs --batch F<n>` under the original native command owner.
Direct adapter calls can inspect behavior but do not alone create a qualifying check-run receipt.

Keep all private task examples, adopter identities, receipts and runtime reports outside source.
Source contains generic contracts and synthetic fixtures only. Preserve concurrent dirty work,
installed pins, native conversations and normal hooks.

## Fixed decisions

- Reuse the current chat/session/worktree binding and Task/Attempt owners; do not create a new store.
- Read-only task facts are separate from open-task execution/decision admission. Terminal or blocked
  status can be reported without permission to resume or accept work.
- Use one versioned `plan-reference` task item, with exact path, batch and normalized definition digest.
  Parsed bookkeeping and explicitly marked commentary changes do not invalidate it; changed definitions do. Forks do not inherit an active batch.
- Preserve whole permitted metadata availability and current generous allowances. No small per-call cap.
- Supply status facts independently of JEV availability. Preserve full current intent and mixed requests.
- Code owns progress bookkeeping, receipt joins and lint. The coding model remains fixed.
- Changed input during one active native turn gets exact entry identity and shares the original
  context family. Current duplicates replay; returning to earlier text creates a predecessor-bound
  occurrence. Continuation admission and local fallback preserve spending and earlier receipts.
- Use the existing evaluator and original evidence. Unknown acceptance, consumption or cost stays unknown.
- No new per-edit checks, background watcher, source scan merely to prepare a progress answer or blanket task inference.

## Plan format and proof cadence

This plan adopts the shipped `governance-plan` format with stable F0–F5 batches and I/V/C slots.
Its declaration binds the specification's definition digest and all twelve criteria; exact captures remain separate. The source-only
`source-4-1` pack declares explicit `4-1-F0` through `4-1-F5` stages; it has no pre-commit stage.
Its normal JSON adapter runs the declared native Node tests and existing no-emit typechecks, hashes
the complete declared regular-file source/dependency closure before and after, and refuses input
changes. Native command logs and cleanup remain with the external check owner. The adapter invokes
the configured TypeScript compiler directly instead of npm's `.bin` symlink aliases; package scripts
must still match the declared native mapping. Generated test fixtures remain owned by existing tests.
The adapter also records Node version, executable path and a complete executable hash in the original
JSON evidence, rejecting pre/post toolchain changes. The native input manifest retains its existing
workspace-file schema; later toolchain freshness requires separate observation. Native tests receive
the existing process owner's credential-free environment, including no inherited `JEV_TOKEN`.
No documentation check or source unit test substitutes for actual installed/archive execution,
semantic comparison, main-model consumption or product acceptance.

All verification slots start unchecked. Only a qualifying original native check run can complete
them through the existing updater. Earlier direct test results are useful evidence with their exact
scope; they are not retroactively fabricated into native check-run receipts. Unstructured plans
elsewhere remain valid documents and need no retrospective conversion.

Finish each coherent batch, including its related bindings and regression tests, before the default
checkpoint. A helper or file finishing is not another check or review boundary. Run earlier only to
resolve a named blocking uncertainty or reproduce an observed defect. Group corrections and repeat
failed/invalidated owners only. Keep unchanged passing proof. Follow the
[validation strategy](../../governance/validation-strategy.md).

At each seam, record implementation, verification and closeout separately. Update current/next and
retained evidence before dependent work. Use the typed updater once adopted. Commit the completed,
verified owned batch when authorized, with normal hooks; do not add another commit just to record it.
Writers may work in independent owned source areas. Batch completion still follows the declared
dependencies and coherent checkpoints. A bounded read-only review may replace investigation a
writer would otherwise repeat; it does not introduce default runtime delegation.
