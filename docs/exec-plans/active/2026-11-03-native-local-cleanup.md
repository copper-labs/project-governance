# Original native local cleanup

A successful native-supervised build can remain unknown solely because its wrapper omitted a
second owner closure report. The operator reviewed and approved the bounded evidence-rule repair.
Extend the existing explicit local-host release selection, without another command, duplicate
report, registry edit, device action or ordinary stage replay. Keep adopter approvals and evidence
outside source. The workflow/device specification owns the accepted input and scope declaration.

The owner explicitly declares local producer/storage obligations through the existing local-host
selection. Require one settled original native stage, exclusively local reservations, exact original
native bytes/identity, confirmed cleanup, full recorded membership and fresh complete process/group
absence. Keep original worker, reader/generation, snapshot and atomic whole-set release fences.
Never infer external mutex/service/device closure from native process absence or an opaque name.
Do not weaken the existing report or separately approved failed-observation routes.

- [x] Implement the exact native receipt alternative and preserve original result bytes.
- [ ] Complete focused positive/negative/retry/generation and installed checks; typecheck/build.
- [ ] Reconcile required independent Opus review and exact archive release proof.
- [ ] Record qualified stable publication/readback and preserve deliberate adopter pins.

One coherent batch covers selection, source contract and regression fixtures. Run the affected
local-release, observed-local and reconciliation boundaries, then declared full engine/exact archive
proof because the resource evidence contract changes. Reuse unchanged harness/script originals
where source, packaging inputs and claims match. Keep source and installed proof distinct. No test
or cleanup is ordinary accepted development, product acceptance or a measured token/time saving.
