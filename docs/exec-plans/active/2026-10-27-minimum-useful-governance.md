# Minimum useful governance

The operator approved implementation of the reviewed simplification, independent Opus 5.5 review
at high effort, reconciliation and stable publication. Target 4.4.0 builds on published 4.3.0.
Adoption remains deliberate. No existing project profile, runtime pin or grant changes on publication.

## Settled scope

Use ordinary configured checks for verified isolated work. Keep workflows for shared resources,
devices, services and multi-stage cleanup; no automatic command classifier or alternate executor.
Add a normal installed workflow binding entry through the existing host adapter and exact task/action
binding. A deliberately configured trusted-development policy permits that binding without another
human dialog. Missing configuration preserves operator review. Invalid configuration refuses.

The existing profile owns the opt-in and exact permitted declared resource identities and credential
names. Empty lists permit none. These are configuration checks under the existing developer-account
trust model, not a sandbox or authenticated proof of human consent. Mutable build/test code stays
trusted. Actual host access controls, project custody guards and task restrictions remain effective.
Changing credentials/resources outside the chosen policy refuses; it does not silently broaden scope.

Reuse ordinary action and workflow binding formats, receipt journal, original-run identity, input
capture, cancellation, process owner and cleanup. No grant table, expiry, authority contract prefix,
aggregate budget ledger, generic policy service or new execution lifecycle. Policy applies when
binding a new action; withdrawal of already bound work uses existing task/cancellation owners.
Fresh source/catalog/driver bytes receive a fresh exact binding, never a rewritten old receipt.
Task changes still stop later ordinary stages; cleanup remains possible. No automatic stage replay.

The separately staged batch-admission candidate is excluded. Its useful intent is retained as
ordinary guidance: coherent batches, focused checks and evidence reuse. Required plan readiness,
exception-driven early diagnostics and native-host lockdown are not prerequisites for ordinary
checks in this release. Preserve the candidate's staged work; any future integration requires a
separate reconciled scope, rebase and new version. Existing hooks and release gates remain required.
