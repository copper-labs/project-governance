# Next major verification and semantic review delivery

## Scope and baseline

The operator approved all five recommendations from the transcript comparison and instructed us to
begin development for the next major release. The target is 4.0.0; the current published compiled
runtime is 3.0.0-rc.10.9. Do not relabel the existing release or update adopters during source work.

runtime owners remain authoritative; the release process owns publication.

this plan's existing proof. It owns neither a second release process nor another runtime gate.

fixture, optional probabilistic review and fixed model defaults. DL01/DL02 capture currently skips
non-JS/TS inputs. Git checks occur at declared stages; the native Stop hook observes usage rather
than checking completion. A passing installation does not prove an existing conversation can
continue. Preserve the already edited worktree guide and all unrelated work.

## Validation cadence

Complete a meaningful implementation batch before its default focused owner checks. Include an
integration seam only when changed behavior crosses it. Earlier checks require a named blocking
uncertainty, reproducer, failed proof or new risk; a slice, helper or file finishing does not start
another test/QA cycle. Record failed and invalidated evidence here, then rerun affected owners.
Update plan checkboxes and current/next action at checkpoints, completed batches, material blockers
and handoffs. Make one owned local commit at each completed verified implementation seam when
authorized, including its plan update and counting normal hook execution once. Preserve unrelated
work; a blocked or paused batch may remain uncommitted with its reason recorded. Consolidate
source/document sign-off at a coherent boundary; broad suites run once for the final candidate unless
relevant invalidation or a named required coverage gap warrants repeating them. Runtime reports and
package test directories live outside this checkout. Clean only run-owned temporary resources.

## Simplification constraints

Keep one runner, one source-subject owner, existing receipts and fixed model defaults. No background
watcher, general mutation system, automatic delegation, added policy language, universal result
cache or extra approval form. Extend known owners only when a reproduced failure or testable
capability gap warrants it. Prefer an existing stack tool over another classifier for mechanical work.
