# RC10.8 consultation and command completion reliability

A scoped review can prepare a valid compact packet while retaining more than 1 MiB of inventory
diagnostics. The detached launch reader incorrectly applies its narrative default to that generated
receipt. Its combined catch then calls the refusal an approval change. Individual optional originals
also encounter the old reader default despite the accepted 16 MiB capture declaration.

The [provider specification](../../specs/provider-agent-skills.md#compiled-consultation-reliability)
owns the correction. Private adopter evidence and reports remain outside this checkout. This batch
does not update an active adopter, change model selection, add a consultation runtime or remove
source freshness validation.

The same patch also owns a verified normal-check completion gap. A recorded descendant can leave
the original process group and finish shortly after its checker exits; supervision previously
declared cleanup unknown without observing that shutdown tail. The documented check-level recovery
handler also lacked managed invocation admission. The same admission omission affected the
existing `check-output` selection command; it also writes decision receipts and spending. The
[execution contract](../../specs/engine-workflow-and-device-contract.md#recovery-through-the-managed-launcher)
owns both corrections. The [worktree guide](../../developer/guides/source-control-and-worktrees.md#keep-an-existing-conversation-usable-after-an-upgrade)
clarifies existing chat identity and avoids whole-host restart advice. No automatic host reattachment
or project proof renewal belongs in this patch.

## Ordered delivery

1. Reproduce a ready receipt with a retained inventory of roughly ten thousand paths and a compact
   model packet. Distinguish prelaunch refusal, native failure, output allowance and stale follow-up.
2. Align generated record write/read allowances through a small shared record owner. Revalidate
   optional originals with the existing source capture reader. Preserve ordinary-file, identity,
   required-guidance and policy checks.
3. Separate context refusal from authority refusal and keep prelaunch refusals out of model
   qualification invalidation. Explain the consultation skill/native executable boundary and the
   existing fresh-review recovery path after source changes.
4. Prove the focused boundary, review the completed correction and prepare the compiled release
   candidate. Publish and verify its exact archive only in the release batch; deliberate adopter
   updates remain separate.
5. Admit check reconciliation and output selection as managed writes and prove recovery's refusal/success through the shipped
   launcher. Preserve exact reservation ownership, failed historical results and unrelated work.
6. Reproduce a successful checker whose recorded detached descendant finishes afterward. Observe
   that owned shutdown within the existing grace; preserve unknown outcomes when absence cannot
   be established. Recheck native, provider and guardian completion before preparing a new archive.

## Simplification boundary

Use the existing source reader, context selector, process owner and consultation route. Share only
the generated-record allowance and persistence functions. Do not add another index, background
watcher, provider wrapper, automatic retry queue or new model. Fresh review submission already
provides the recovery path after corrective changes; automatic continuation refresh is deferred.
