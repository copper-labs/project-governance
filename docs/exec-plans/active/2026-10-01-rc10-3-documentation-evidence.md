# RC10.3 Documentation Evidence Repair

Whole-inventory documentation checks can reinterpret copied source indexes relative to an evidence
directory. Raw reviewer reports also lack authored metadata. That creates repeated failures in new
projects without identifying a defect in their live guidance. Keep adopter evidence outside this
checkout and preserve frozen copies; do not rewrite them to satisfy current-document rules.

The [documentation specification](../../specs/developer-documentation-system.md#compiled-runtime-live-documents-and-saved-evidence)
owns the accepted role and lifecycle contract. One implementation batch updates its compiled checker,
portable authoring guidance and installed greenfield release proof. No profile schema migration,
adopter upgrade, provider invocation or broader retrieval change is required.

## Delivery and proof budget

- [x] Classify the conventional evidence namespace as raw artifacts, retaining authored summary
  checks, frozen-copy handling and explicit catalog reference/guide overrides.
- [x] Accept established proposal and decision lifecycle names. Keep lesson and active-plan
  constraints, identity, dates, local-link safety and catalog validity blocking.

  cross-repository citations and missing live targets as separate findings.
- [x] Add focused staged/whole checks and installed greenfield proof. Successful evidence retention
  must coexist with a failing broken live guide and unchanged snapshot bytes.
- [x] Run focused tests/typecheck; replay representative evidence read-only outside this checkout.
- [x] Freeze the implementation for one Opus 5.5 medium review. Reconcile concrete findings and
  recheck only an affected correction seam when required.
- [x] Run one full release checkpoint: compiled and retained Python tests, type checking, wheel
  boundary and exact installed archive proof. Investigate a failed owner before repeating proof.
- [ ] Publish authorized `3.0.0-rc.10.3` through the existing release workflow and verify source,
  archive, lock/update metadata and immutable prerelease readback.

## Acceptance boundaries

A new project can retain review reports and relocated source snapshots without false metadata,
link or duplicate-ID failures. Live evidence summaries and cataloged guides still fail when broken.
Artifact handling never grants an external read or hides an active execution plan. All applicable
non-documentation checks retain ownership. Whole-inventory and staged selection use the same role
rules and captured target graph; unrelated working-tree additions cannot satisfy a staged link.

Offline fixture inference continues to qualify existing greenfield context behavior. This
deterministic documentation repair does not require new live JEV calls or establish token savings,
device acceptance, or a clean adopter-wide inventory. Installation into another project remains
separate authorized work.

## Focused qualification

Ten focused checker and catalog tests and type checking pass. The final installed greenfield
candidate also passes its strengthened staged, summary-failure and all-artifact assertions. A
read-only replay uses one captured inventory for both the preceding release and this candidate;
snapshot, raw-report and lifecycle false positives disappear while live metadata and link findings
remain visible. Exact adopter paths, counts and source digests are retained externally. The
greenfield proof exercises the published command surface and preserves snapshot bytes through
both a controlled failure and its repair.

Opus 5.5 medium reviewed the frozen implementation and its focused correction. The invalid-catalog
boundary is now explicit and tested: catalog validation blocks first, and guide findings become
visible once its declarations can be read. A separately staged guide uses its captured catalog even
when the working copy removes the route. Lowercase artifact-directory conventions and reserved
summary filenames are documented. Installed proof covers whole and staged success, broken live
guidance and summaries, repair and every raw artifact's unchanged bytes. No concrete correction
regression remains. An additional artifact counter and duplicate fixture workspace are not needed
for this bounded repair.

## Release qualification

The frozen implementation passed 807 compiled tests, 470 retained Python runtime tests and type
checking. Retained wheel proof and the final isolated installed archive passed. The strengthened

Existing installed context, parser, host API, staging and decision fixture proof also pass. Offline
synthetic inference remains distinct from live provider readiness or accepted-development benefit.
