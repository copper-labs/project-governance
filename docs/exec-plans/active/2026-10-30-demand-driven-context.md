# Delivery plan

Owner: [specification](../../specs/engine-demand-driven-context.md).
Operator authorized specification, Opus 5.5 high and Gemini Argon high reviews, reconciliation,
implementation and stable release. Publication does not authorize adopter upgrades or paid JEV
experiments. Work starts from stable 4.4.3 in an isolated checkout.

## Batch 1 — design and review

- [x] Diagnose entry-triggered optional indexing and paid selection; inspect existing telemetry owners.
- [x] Draft the specification and declare scope, compatibility, evidence and economic limits.
- [x] Obtain independent Opus 5.5 high and Gemini Argon high reviews.
- [x] Reconcile findings with source; amend the specification before implementation.

## Batch 2 — implementation and focused proof

- [x] Introduce request modes at the existing context-route owner. Native entry skips optional work.
- [x] Preserve required guidance, exact inputs, local fallback, source permissions and family limits.
- [x] Permit empty local optional results; update native guidance and shipped command documentation.
- [x] Extend existing receipts and passive status with mode and linked-evidence coverage.
- [x] Add focused regressions for dispatch, index preservation, local/semantic behavior and telemetry.
- [x] Run typecheck and owning context/prompt/telemetry suites at this coherent checkpoint.

## Batch 3 — review and release proof

- [x] Obtain implementation review and reconcile material findings with focused rechecks.
- [x] Freeze one stable candidate; run broad source proof required by selection-contract change.
- [x] Build the compiled archive and run installed/greenfield and changed-entry proof against it.
- [x] Record exact source/archive/review bindings and residual live-effectiveness limitations externally.
- [ ] Commit owned changes with normal narrative and hooks; publish stable minor release manually.
- [ ] Verify tag, archive digests, lock/update metadata, immutable stable/latest release and readback.

## Stopping rules

No new services, intent classifier, automatic model choice, blanket disclosure, threshold changes,
adopter migration or new acceptance authority. Do not claim savings before matched accepted work.
If provider reviews or release gates fail, keep verified work and state the exact unfinished gate.
Reuse unaffected proof; repair failed owners without restarting unchanged work.

## Qualification reconciliation

Broad source proof exposed legacy automatic-retrieval expectations. Their fixtures now request paid
selection explicitly and retain disclosure, freshness, symlink and non-execution assertions. Follow-up
proof covers the changed context, decision, native-entry and telemetry boundaries; unchanged source,
harness and packaging originals are reused. Installed native-entry and continuity fixtures distinguish
required-only entry from explicitly requested indexing. A transient process-inventory timeout is
retained separately from assertion failures and rechecked through the affected consultation owner.
Runtime payload changes are compared file-by-file before reusing any prior installed proof. Every
release claim and exact archive binding is retained in the external release record, not adopter data
in this project-neutral plan. No live JEV experiment or adopter migration is included.
