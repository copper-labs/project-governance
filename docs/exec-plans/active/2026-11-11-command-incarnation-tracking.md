# Preserve native command process incarnations

New command runs must distinguish an exited recorded process from a live replacement, retain every
proven descendant incarnation and signal only matching identities. Legacy or incomplete records stay
conservative. Existing failed receipts are immutable; this change grants no adopter installation,
historical reservation recovery or remote publication.

One coherent source batch owns the request/launch/member capability, complete native process
inventory, collection, signalling and cleanup readback. It does not change resource/installation
registries, task bindings or higher-level workflow recovery policy. The canonical explanation lives
in the provider lifecycle specification.

- [x] Reproduce positive replacement and guardian cleanup failures with a real inert fixture process.
- [x] Implement the version-bound incarnation contract and fail-closed legacy handling.
- [x] Complete focused process/isolation regressions, source typecheck and affected compiled proof.
- [x] Freeze the source, review independently and reconcile for the normal source hook boundary.

The checkpoint includes reused and original-live processes, unavailable identity, unanchored groups,
anchored descendant reuse, guardian restart, immutable failure evidence and no native replay. Broader
proof covers the affected process lifecycle and installed package owners. Reuse unchanged release
evidence; do not repeat application suites or unrelated provider/Cowork journeys. Run lightweight
source proof first and serialize any substantial package/full-suite checkpoint with the owning
workstream. Keep operational evidence outside this checkout.
