# RC10.4 Large Evidence and Review Reliability

The normal context router captures every working-copy change before it prepares a scoped review.
It applies a content-read bound during identity capture, so an unrelated generated artifact can
block the provider before launch. Automatic retrieval also admits saved evidence that should be
represented by an authored summary. Repair these boundaries together in one small release batch.

The [context specification](../../specs/engine-rc10-context-use.md#rc104-saved-evidence-and-capture-boundary)
owns the accepted contract. Exact adopter paths and operational evidence remain outside source.
Work solo on the correction; one focused independent reviewer checks the frozen batch.

- [x] Publish authorized `3.0.0-rc.10.4`; verify exact source, immutable archive, lock and deliberate

## Independent correction review

Opus 5.5 medium identified two classification edges: an explicit evidence read must remain
observable, and catalog-declared guides must retain their authored role. Automatic discovery now
uses a separate artifact gate while explicit reads retain their safe-path owner. The context
catalog, candidates and disposable source index share the documentation owner's declaration
exemptions. Focused tests cover both edges; the correction review closed both findings.

## Local release qualification

The compiled engine, continuity and script suites cover 812 cases. The retained Python suite
covers 470 cases. Two development-environment failures were resolved by using the declared
dependencies and replaying their owning suites: provider skill selection and wheel reproducibility.
Type checking, wheel boundary inspection and the complete installed-package proof passed. Native
greenfield entry covers large untracked evidence, selected guidance, task binding, replay,
missing-token and billing fallback, documentation checks and normal ownership closeout. The
greenfield test keeps context capture separate from validation materialization's existing body
limits. A source-quality finding was resolved by separating fixture setup and offline recovery
into small test helpers.

## Acceptance and adoption boundary

Artifact exclusions do not remove files from governance validation, broaden hosted disclosure,
shorten mandatory rules, waive checks or change the selected coding model. The body and staged
first-commit allowances retain their owners. Native preparation must succeed through the packaged
entry point, with missing credentials retaining local fallback. Fixture inference proves wiring,
not accepted-development quality or savings.

Adopter upgrades remain deliberate. Do not modify an active agent's checkout or release its live
ownership. Once agents reach a safe seam, use supported session closeout and the verified runtime
update operation. Preserve application files, staged content and prior receipts.
