# RC10.2 New Project Operational Proof

Configuration eligibility is not provider health. Existing compiled and installed-package tests
passed, and prior live retrieval regressions succeeded under explicit profiles. A later fresh
installation nevertheless delivered fallback only, hid the provider's billing denial, excluded
newly authored knowledge through an unchanged disclosure scope, and returned excessive route
diagnostics to the coding agent. Keep adopter details and evidence outside this checkout.

## One implementation batch

- [x] Retain HTTP status and a fixed actionable classification for billing, authentication,
  request rejection, overload and provider failure. Preserve deadlines, cooldown, budgets and
  fallback. Never retain raw response bodies, arbitrary provider messages or credentials.
- [x] Make passive decision diagnostics distinguish configured eligibility from observed
  success/failure/unobserved health using current-version, current-configuration receipts.
- [x] Expose local inventory versus approved metadata/body coverage in passive context diagnostics.
  Do not automatically broaden disclosure. Explain the deliberate profile repair when a new
  project grows beyond its initial approved paths.
- [x] Return compact selected material, references and a small status from the normal context CLI.
  Preserve full receipts and provide explicit full JSON for diagnostic consumers. Native prompt
  replay retains its identity, mandatory content, omissions and failure information.
- [x] Treat an unborn added-file inventory as coverage, rather than pinning every bootstrap file.
  Keep required guidance, explicit paths and task declarations first. Prove the first task receives
  its project brief before an initial commit exists.
- [x] Provide explicit cross-repository read accounting with verified Git workspace identity,
  relative source path and digest. Do not remove local-path protections or disclose external
  source to JEV. Keep external reads separate from local packet misses.
- [x] Add a dedicated installed greenfield suite: actual installation into a repository with no
  initial commit; growing project records and local skills; native-format prompt entry; binding
  and repeat; successful selection; missing token; billing denial; narrowed disclosure; compact
  normal output; full diagnostics; source references; cleanup and existing checks.
- [x] Require this offline suite at package publication. Use deterministic fixture inference for
  offline branches. Provide a separate exact packaged path for live JEV on synthetic content when
  the operator's account has credit. A fallback cannot satisfy its success assertion. A billing
  blocker does not delay the tested diagnostic hotfix, but live adoption qualification remains
  pending; never label configuration-only or fixture proof live readiness.
- [x] Run focused tests/typecheck, freeze the candidate, obtain one Opus 5.5 medium review, reconcile
  concrete findings, then run the full compiled suite and installed archive once.
- [x] Publish immutable `3.0.0-rc.10.2` through the existing release workflow under the operator's
  authorization; verify exact source, archive, metadata and independent CI. Do not update an
  active adopter or alter its authored policy as a publication side effect.

## Acceptance

The suite must prove what the operator receives through shipped entry points, not only library
composition. A provider denial must name the operational cause while safe local work continues.
A configured token alone never proves JEV success. Fresh-project coverage changes must become
visible without silently granting disclosure. Ordinary context output must omit repository-wide
index diagnostics while retaining selected evidence and access to originals. External reads must
not be misreported as local retrieval misses. Preserve unknown model usage and accepted outcomes;
this hotfix makes no token-savings claim.

Live adoption proof depends on usable provider credit. If unavailable, publish only the locally
and independently tested corrections, retain the external blocker, and do not claim live acceptance
or successful ordinary JEV use. Re-run the packaged live suite once the account is funded.

resolved. Interrupted calls no longer create false provider-health failures; compact output retains
