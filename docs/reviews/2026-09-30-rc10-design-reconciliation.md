# RC10 design review and simplification

Owner: [RC10 specification](../specs/engine-rc10-context-use.md) and
[implementation plan](../exec-plans/active/2026-09-29-rc10-context-use.md).
The operator requested review, reconciliation, simplification, then implementation and simulation.
Claude Opus 5.5 ran at medium effort, without fallback, in read-only plan mode. Its retained audit
confirms successful completion and no workspace changes. Private evidence and the raw review stay
outside this reusable checkout. This is design review, not approval of unimplemented runtime code.

## Reconciliation

| Finding | Source assessment and decision |
| --- | --- |
| Separate procedure stage duplicates passage selection | Accepted. Feed declared sections directly into the existing passage queue, interleaved with ordinary source units. Retain the existing questions, budget, deadline and delivery owner. No additional classifier stage. |
| Flat Markdown spans omit child steps | Accepted. Record heading levels, derive ancestry and end parent sections at the next same-or-higher heading. Version the extractor and prove nested constraints survive delivery. |
| Descriptor/body sharing coupling is unstated | Accepted. Existing source permission authorizes descriptions and bodies for those paths. Passage inference still needs explicit enablement. Unapproved procedures return local references. No new sharing switch. |
| Host alignment and private outcome gates exceed runtime proof | Accepted with a boundary. Release proof checks entry identity and reproducible packet contents; actual chat attachment and accepted-task efficiency remain adoption evidence. Keep private source-backed cases as effectiveness checks, without claiming native-agent acceptance. |
| Repeated instructions and paths dominate payload | Accepted. Implement one compact layout; retain the old wire shape only as an external comparison. Keep meaning and source identity. Qualification still checks inference, because moving instructions can change answers. |
| Wrong-worktree diagnosis needs a sibling lookup decision | Accepted. No sibling index search. A missing local entry has a named unavailable reason; a confirmed mismatch requires local provenance. Code cannot enforce every native tool directory. |
| Exact answers already replay | Accepted. Preserve those owners. Add plain-command packet reuse through the current entry revalidation and record reuse distinctly. No fuzzy cache or new budget. |
| Directory limits hide recent telemetry | Accepted. Reuse the bounded SQLite projection owner, filter before limiting and label the receipt fallback and write-coverage gaps. Operational evidence remains authoritative. |
| Native evaluation isolation lacks an owner | Accepted. The initial simulation keeps answer labels out of selection input and scores afterwards. Autonomous outcome comparison is later work requiring real tool/process isolation. |
| Doctor may become another evidence evaluator | Accepted. Add compact configuration coverage and references to retained entry/route facts. Do not rescan source or probe JEV during doctor. |

One review detail needed correction: the passage byte reserve is the smaller of 65,536 bytes and
a quarter of the configured total. It is not a quarter of a multi-megabyte allowance. The planning
arithmetic also separates summed HTTP work, concurrency waves and the shared admission constraint;
none alone establishes actual operation wall time.

## Accepted simplifications

1. **Use the passage pipeline for procedures.** We retain useful runbook selection and whole-section
   delivery while avoiding another stage, question identity, clock and reserve. Procedures remain
   eligible independently of file ranking.
2. **Return the current packet for an explicit entry repeat.** Revalidate its receipt and sources through
   the duplicate-hook owner. A bare shell command cannot infer the host turn; require the hook entry
   reference when turn identity is unavailable. Do not rebuild a selector or infer intent from the old task.
3. **Ship one compact wire format.** Hoist instructions and carry each path once with short local
   references. Keep comparison formats outside production configuration; no new operator knob.
4. **Reuse existing permissions.** Explicitly explain descriptor/body coupling and expose approved
   versus transmitted facts. This preserves scope control without another disclosure mode.
5. **Keep doctor small.** Report configuration and link current evidence. Receipt owners retain the
   details instead of doctor creating another independent assessment.
6. **Separate retrieval proof from efficiency proof.** A generated large catalog, nested procedure
   cases and real frozen source cases prove selection/delivery. Ordinary accepted development later
   measures tokens, time and rework; no autonomous evaluator service is added to RC10.

These changes remove duplicate mechanisms, not required behavior. Complete eligible inventory,
explicit partial coverage, fixed coding model, required guidance, original references and missing-token
fallback remain. The maintained index and transactional spending remain SQLite-owned.

## Implementation boundary

The specification and plan incorporate these decisions. Recheck the affected design findings before
runtime implementation; at the completed candidate seam review code and local proof. Live simulations
use isolated retained source snapshots and approved sharing, never active adopter processes or builds.

## Focused recheck corrections

The affected recheck closed the original findings and identified four remaining rules. The plan now
states them: nonoverlapping parent procedure units; alternating procedure/source allocation using
remaining family capacity; explicit entry/session validation with no invented shell turn; and the
existing 8 MB ceiling with compact-quality qualification as a release stop. Tests cover competing
procedure/assertion evidence, nested assessed bytes, two sessions and absent newer markers.
Layout upgrades invalidate old exact-layout replay without refunding spending. Receipt fallback also
filters before limiting. These are corrections within the existing owners, not additional mechanisms.

The final wording recheck found two contradictions rather than a new design defect. The passage
queue now consistently alternates procedure and source units. An explicit validated entry is declared
reuse; a bare command cannot infer the native turn. The initial two review audits were unchanged;
the last wording audit overlapped the author's runtime edits and is not an unchanged-candidate audit.

## Simulation-driven corrections

The first large-corpus runs reached the operation cutoff before decisive procedure delivery. Wire
compactness alone did not qualify the release. Two concrete causes were corrected within existing
owners: the fact cache retained too little extracted metadata for the large supported corpus, and
provider admission retained conservative byte estimates after valid measured token usage arrived.
The fact allowance is now 32 MiB inside the current 64 MiB index envelope, with an extractor version
change. Known usage settles the rolling rate reservation; unknown usage remains conservative. No
request ceiling, concurrency ceiling, family allowance or operation timeout is relaxed by settlement.
These corrections require affected tests, a repeated frozen tuning case and candidate code review.

An independently authored fresh case exposed a distinct metadata bug. Correct source files had high
ordinal ranks but uncertain scores below the positive threshold. The selector discarded those ranks
and reverted to lexical background. The correction separates advisory file ranking from confirmed
passage evidence: answered uncertainty can choose the next original to inspect, without changing
confidence thresholds, excerpt allowances or execution authority. Negative/missing and shadow
paths retain their fallback treatment. Counts and previews preserve the uncertain label. A literal
Kotlin enum-name extraction error was also corrected with cache invalidation and focused proof.
The first failed run remains retained; reusing it after this change is regression evidence, not a
second independent holdout or an accepted-task saving claim.

The repeated live run identified the same confidence/ranking coupling at packet delivery, plus a
native declaration boundary omitting its attached test annotation. Native annotated ranges now retain
their leading annotation. Validated positive/uncertain passage scores both guide ordinary quote
sequencing and supported role balance; required pins and confirmed-only larger excerpts remain
separate. Uncertainty stays explicitly labelled and never marks a procedure selected. This revises
the earlier within-file-only advisory restriction because the retained run showed it suppressing a
useful source quote while filling the packet with weaker background. No confidence threshold,
total packet allowance, source disclosure or execution authority changed.

## Retrieval review after tuning

Earlier in implementation, Opus 5.5 medium independently reviewed the tuning receipts and selection owners,
without fallback or workspace changes. It identified two necessary changes: retain answered uncertain
scores for advisory ordering inside a file, and remove procedure declarations' positive-only delivery
filter. A separate typed unit-order field avoids leaking uncertain advice into positive promotion,
pinning or the larger procedure allowance. The initial restriction also excluded role balancing;
the later retained simulation above justified revising that advisory sequencing rule. Global
confidence regions remain unchanged.
Source-range order resolves ties independently of dispatch composition. Scores order units inside
each file; the initial correction retained file order and first-unit-before-upgrades delivery. This is
an explicit amendment to the earlier rule, not a
reinterpretation of uncertainty as authority.

The review also found evaluation boundaries to record before qualification: some frozen proof groups
require multiple complete units; one tuning-label correction followed earlier tuning results; the
held-out local fallback baseline was scored before live qualification. Keep those records, preserve
the current proof ranges and report conjunctive groups separately. Do not claim the corrected tuning
labels are independent evidence, or that the fallback baseline was never examined. No downstream
accepted-task or token-saving result is established.

## Corrections exposed by the first live qualification attempt

The first live held-out run delivered three of eight decisive groups. It failed the release gate.
Those cases are now diagnostic regressions, not fresh independent held-out evidence. Enlarging the
explicit source-body declaration from its legacy default of 16 to 64 delivered five of eight groups;
the source window still replaced ranked files after its first 32 with lexical discoveries. Full
metadata coverage therefore did not establish source-body or packet coverage.

Three additional, general corrections address the measured causes. They extend the narrower
retrieval-review recommendation and require completed-candidate review:

- Fill the complete configured source-body window from metadata order. Keep explicit expansion;
  do not discard ranked files merely to reserve unused lexical discovery capacity.
- Preserve useful uncertain sections alongside a positive section within the ordinary file slot.
  Keep a separate advisory map, the positive anchor, uncertainty labels and the unchanged positive
  region. If the mixed excerpt cannot fit, preserve valid positive evidence. Do not grant uncertain
  sections the larger procedure allowance.
- Balance explicitly declared, answered procedure excerpts with source files under the existing
  packet envelope. Initially preserve metadata order within each category, without comparing uncertain scores
  across files. This uses the operator's declared category; it creates no pin, selected status or
  execution authority and never promotes an undeclared uncertain document.

Keep the original failed receipts, source proofs and configurations. A changed packet or source
allowance is a distinct configuration experiment, not a retrospective pass. Successful regression
simulation alone will not establish accepted-task savings or general retrieval accuracy.

## Reconciliation of the measured retrieval limits

A focused Opus 5.5 medium review found an additional substitution defect: an uncertain procedure's
strongest section was skipped for size and replaced by weaker sections. The correction quotes a
partial window inside that strongest section at the ordinary allowance, with incomplete labels and
the original/prelude reference. The positive complete-section path remains intact. The review
recommended retaining the preparation cap pending evidence that unseen units would change delivery.

A subsequent bounded diagnostic supplied that evidence. A decisive unclassified source unit became
positive when JEV saw the complete approved body instead of a delivery-sized clip. This motivates
two general corrections, rather than another threshold: separate approved classification input from
main-model delivery size, and prepare alternating units against remaining family bytes instead of
a separate 256-unit ceiling. Exact wire fitting, source capture, shared admission and the unchanged
operation deadline retain their authority. Preparation and packing duration are now measured.

Source inspection also found an extra 8 KiB ceiling in native optional delivery. Remove it and
respect the existing declared route envelope; qualification must exercise the installed native hook,
not just manual retrieval. These changes require affected proof and completed-candidate review.
The original three diagnostic corpora remain consumed tuning/regression evidence. New independent
qualification cases must be frozen before their live run. No accepted-task or savings claim follows
from either successful packet simulation or fixture inference.

## Packet-fitting correction and final simplification

Complete classification recovered meaningful units but did not by itself deliver them. Recorded
answers exposed two local fitting defects: unassessed background formed barriers ahead of confirmed
evidence, and earlier files consumed extra sections before later files received theirs. Remove the
segment/barrier rule, reuse the existing complementary role/category order, and pack useful evidence
in per-file rounds before ordinary background. Required guidance and explicit pins remain first.

The ordinary per-file slot protects initial breadth. Further validated positive source spans can
spend only remaining exact packet capacity, without a new profile setting or paid request. Retain
every already delivered range; label incomplete additions and reject any later ordinary excerpt
that would erase an earlier addition. Uncertain-only spans do not gain that larger allocation.
This unifies capacity with the packet's existing owner instead of adding another exclusion threshold.

Replay of the recorded classification answers now delivers all eight decisive evidence groups in
the three consumed regression cases under their unchanged packet allowances. This is diagnostic
proof of the local fitting repair, not independent retrieval qualification or accepted-task savings.
Fresh reviewer-authored cases and installed native-hook proof remain release requirements.

The first-event refusal test also found that a telemetry write could precede creation of its context
state directory. The shared projection writer now creates that directory on writes; passive reads
still create nothing. Typed refusal receipts retain zero provider attempts without raw operator text.

## Completed-candidate review reconciliation

The final frozen-candidate review used Claude Opus 5.5 at medium effort with no fallback and no
repository writes. It identified an installed-fixture failure, an argument-based current-intent
bypass, and incomplete telemetry ingestion. These block qualification until affected proof passes.

- Commit the installed fixture baseline only when there are staged changes. Preserve the original
  unborn-installation proof and require the exact `entry-source-stale` refusal after a source edit.
- Require the current `--task` request for fresh shell selection regardless of its other flags.
  Exact `--entry` replay remains separate. Update the older entry specification and guide example.
- Treat SQLite rows as prioritized references to original receipts. Scan remaining bounded receipts
  in the same reader so legacy history, standalone context receipts and a missed concurrent write
  remain observable. Report partial scan, cache retention and unverified write coverage separately.
  New decision/context receipts name their producing runtime; unversioned history cannot be
  attributed to a requested runtime. No backfill, new join store or write-retry loop is introduced.
- Alternate procedure declarations and ordinary metadata-ranked sources within the existing
  capture window, after removing explicit pins from both queues. Preserve all original references
  and named omissions; do not solve crowding by reducing the permitted declaration list.
- Resolve a nested working directory to its Git worktree before entry replay. Keep sibling and
  session checks intact. Label a document prelude as a heading, and distinguish unchanged advisory
  ordering from shadow results that were intentionally not applied.

The review's simplification suggestions were checked against each owner's other callers:

| Suggestion | Decision and reason |
| --- | --- |
| Keep only route receipt ID/digest in the saved packet | Retain the exact route snapshot. The durable receipt and returned packet have different shapes; reconstructing the returned packet would add an adapter and risk losing exact replay behavior. |
| Remove fallback packet byte validation as unreachable | Retain it. Native duplicate-hook delivery also calls the reader and can return a non-prepared fallback. The CLI alone is not its complete caller set. |
| Remove the early prompt-refusal metric writer | Retain it. Malformed or unsupported native events can be refused before route selection runs; the route-failure writer does not observe that boundary. |
| Consolidate telemetry readers | Applied. One bounded receipt reader supplies the report; SQL only prioritizes originals. Separate SQL-only and receipt-only aggregators are removed. |
| Keep compact requests, uncertainty labels and evidence rounds | Retain. Each addresses a reproduced delivery failure without adding another pipeline or authority. |
| Add a separate passage-stage deadline reserve | Do not add one. Keep the single operation clock and measured stage omissions. |

Fresh reviewer-authored cases are frozen and hash-verified before their first live run. Their result
must be reported unchanged before any repair against those cases. They qualify frozen-source
retrieval only, not native host adoption, accepted-task efficiency or token savings.

## Cohesive evidence correction from the fresh smoke

The new independently authored cohort's first live run delivered two of six complete groups despite
complete permitted metadata assessment. Keep that failed result. Corrected repeats are diagnostic
regressions, not a fresh qualification claim.

The misses exposed fragmentation: a selected function lacked its sorting helper, an assertion
lacked its fixture, and Kotlin backtick test names were absent from literal extraction. A small
implementation file was reduced to constants without its policy application and default behavior.

Keep small source files intact when they fit the existing ordinary excerpt and approved input.
This removes redundant fragment questions and retains surrounding evidence without another stage
or allowance. Larger source files keep bounded unit selection; include attached declaration prose,
quoted Kotlin names and neighboring small declarations within the ordinary default cluster target.
Advance the extractor identity so existing disposable facts are rebuilt deliberately. Required
guidance, source permissions, thresholds, uncertain labels and the operation clock remain unchanged.

That correction delivered five of six groups on the same consumed cases. The remaining miss was
local packet ordering: a small probability difference between fragments in two files displaced the
highly ranked original. Remove cross-file comparison of uncertain passage scores. Metadata owns
uncertain file order; passage scores choose units inside each file. Confirmed body relevance remains
separate. Keep complementary evidence roles and explicit
procedure balance. Exact replay of the recorded answers then delivers all six groups without new
provider calls or changed allowances. The wider live regression found that confidence groups must
remain distinct: confirmed source bodies retain their relevance order; uncertain ones retain
metadata order. Keep complementary implementation/assertion roles even when one role is uncertain.
Keep a clearly partial later procedure section when it fits the remaining ordinary slot, preserving
the strongest complete section and its prelude. These refinements need affected replay, live
regression and installed proof; all earlier failed runs remain evidence.

The fitting rule is also simpler when it honors the ordinary file slot. Deliver that bounded excerpt
intact where it fits; split larger procedure allowances into section rounds, and retain the first
validated unit if the ordinary excerpt cannot fit. Further confirmed extensions still use remaining
packet capacity in rounds. This keeps a small cohesive policy excerpt together instead of letting
many weak snippets consume the space needed for its later constraints. No allowance is enlarged.

## Final affected recheck and simplification

The focused Opus 5.5 medium recheck found no remaining high or medium code defect in the reviewed
boundaries. Its remaining concerns were qualification claims: library composition is different
from installed native entry, smaller/default profiles retain misses, warm latency is different
from cold preparation, and the proof must identify its exact archive. Keep these distinctions in
the plan, guide, release notes and external evidence summary. Narrow declaration-prose claims to
function declarations; attached arrow-variable prose remains an extraction limitation.

Two small follow-ups close adjacent low findings: telemetry context commands resolve nested working
directories to their Git worktree, and older command examples require current intent. Declared
procedures retain their local fallback opportunity even without hosted-source permission; such
declarations can consume shared capture slots. Do not remove them by conflating local retrieval with
permission to send their bodies to a provider. Missing declarations remain visible references.

The wider regression left one test/implementation pair separated despite complete assessment.
Reuse the existing literal import facts and both current digests during packet fitting. A confirmed
test can bring a captured, non-negative implementation alongside it without a pin, new capture,
larger allocation or positive label. Expose the existing manual excerpt allowance through the native
profile so local evaluations can describe settings the ordinary entry path can actually use.

| Simplification candidate | Decision |

| Add another relationship search, model call or graph store | Use current literal imports in the existing packet builder. Broader inferred relationships stay deferred. |
| Add a second native excerpt setting/ceiling | Expose the existing allowance and shared validator; route total remains authoritative. Keep existing defaults. |
| Remove telemetry's SQLite projection now that originals are scanned | Retain it as recent-read hints for bounded scans. Measure write overhead before removal; it is not a second evidence owner. |
| Derive clustering from each delivery profile | Keep the fixed 3 KiB preparation target documented. Changing it now would alter classifier input and invalidate recorded-answer comparisons without demonstrated benefit. |
| Add more modes, retries or a separate stage timeout | Keep one layout, one operation clock, one shared family and the existing fallback. |

No new background service, procedure catalog, authority layer or agent reporting ceremony is needed.
Final qualification retains the failed cases and names the delivery profile. One actual packaged
command case complements library regressions and installed synthetic-hook proof; native chat
attachment, accepted tasks, cold performance and savings remain field evidence.
